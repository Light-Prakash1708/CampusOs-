# Feature requests

Nothing here is built by default. A request moves to the backlog only when the gate answers are clear **and** backed by evidence from more than one user or customer. When the answers are unclear, it stays logged.

| ID | Date | Requested by (role, college) | Exact problem (their words) | Times heard / people | Current workaround | Blocks adoption? | Existing feature solves it? | Affects willingness to pay? |
|---|---|---|---|---|---|---|---|---|

### The gate (answer for each request before building)

1. Does it solve a repeated problem?
2. How many pilot users hit it?
3. Is it blocking adoption?
4. Is there an existing workaround?
5. Does it strengthen the wedge (verified notices, SGRC, evidence pack)?
6. Does it increase willingness to pay?
7. What technical, security or privacy complexity does it add?
8. Can it wait until V1.5?
9. Is it supported by more than one customer or user?

**Deferred by strategy.** These are not built without explicit authorisation or clear evidence:

- weekly digest, Campus Pulse;
- ERP connectors, Growth Profile, opportunity matching;
- WhatsApp BSP, new AI providers;
- multi-college groups, SSO, payment gateway;
- mentor workflows, NAAC mapping v2, APAAR/ABC;
- recruiter marketplace, clubs/channels, AI memory, student subscriptions.
